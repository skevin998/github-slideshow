# 单文件高保真交互 HTML 交付规范

本文件只定义 HTML 的交付边界、实现状态和验证流程。视觉参数读取 [基础设计规范](foundations.md)，交互读取 [组件与交互模式](patterns.md)，页面和业务流程读取 [页面规范](my-customers-pages.md)，组件选择读取 [Ant Design v4 映射](antd-mapping.md)。

## 交付边界

- 首要交付物为一个 UTF-8 `.html` 文件，可直接双击打开。
- CSS、JavaScript、SVG、标准 Logo 和模拟数据全部内联；不拆分依赖，不使用 CDN、网络字体、远程接口、包管理器、构建工具或本地服务。
- 默认使用原生 HTML/CSS/JavaScript复现 Ant Design v4 的视觉和交互语义，不伪称实际引入组件库。
- 使用简体中文模拟数据，不连接真实 API，不执行真实删除、上传或批量导入。
- 单页任务只覆盖该页面及验证核心流程必需的关联视图；完整模块仍只使用一个 HTML 和内部视图状态。
- 不用静态截图、设计说明或“待开发”占位代替可运行交互。

## 高保真实现

- `:root` 集中映射基础规范中的全部 Token，页面代码不得创造重复常量。
- 标准 Logo 从 Skill 资产提取同一图像数据并内联，不依赖原始桌面路径。
- 信息层级、字段顺序、页面打开方式和返回目标严格遵循页面规范。
- 控件实现适用的 default、hover、focus-visible、active、disabled 和 loading 状态。
- 长名称、空值、无结果、加载、局部错误和失败反馈不得破坏布局。
- 状态必须包含文字；图标按钮必须有 `aria-label` 或等价可读名称。
- 首屏不加入讲解面板、设计标注或调试工具。

## 必须可操作的范围

按本次需求实现对应场景；完整模块需覆盖全部场景：

| 场景 | 需要验证的行为 |
|---|---|
| 应用壳层 | 侧栏展开/折叠、菜单选中、顶栏固定、内容滚动 |
| 我的客户列表 | 查询、重置、分页、每页数量、详情入口 |
| 客户详情 | 五个 Tabs、各 Tab 独立状态、复制反馈 |
| 公司列表三视角 | 分段切换、两种表格筛选、图谱无搜索、各视角状态保留 |
| 总公司分公司列表 | 总公司摘要、添加分公司、行下钻、返回原视角 |
| 公司详情 | 四个二级 Tabs、业务卡跳转、关联总公司/分公司、编辑 Drawer |
| 关联分公司与门店 | 来源下钻、列表行进入详情、视图栈返回 |
| 品牌列表 | 卡片/列表切换、筛选、创建/编辑 Drawer、上传模拟 |
| 产品管理 | 开通状态、loading、成功和可恢复失败 |
| 批量操作记录 | 筛选、状态、结果详情 |
| Drawer | 校验、dirty 关闭、提交防重复、局部刷新 |
| 删除 | 二次确认、取消、提交、成功和失败 |
| 批量设置 | 模板反馈、文件选择、检查结果、执行进度、返回恢复 |
| 通用状态 | 首次加载、局部加载、首次无数据、筛选无结果、局部错误和重试 |

未包含的业务不得为了凑功能增加入口；未实现的能力不得呈现为可点击。

## 页面状态模型

- 筛选草稿和已提交条件分离，保证查询只由明确操作触发。
- 客户详情各 Tab 使用独立状态对象；状态字段以交互模式为准。
- 下钻页面使用视图栈或等价状态保存来源上下文。
- Drawer 关闭后保持背景状态；成功后只刷新关联数据。
- 异步行为提供 loading、成功和失败路径；失败保留可恢复输入。
- 状态只保留在当前 HTML 生命周期；页面刷新后恢复初始状态，不使用 `localStorage` 等跨刷新存储。

## 浏览器标签实现

- 客户详情使用 `window.open` 打开新浏览器标签，以客户编号作为稳定窗口名称。
- 重复打开同一客户时聚焦已有标签。
- 浏览器阻止弹窗时给出提示，不覆盖列表页，也不切换成系统内部业务标签。
- 新标签仍由同一 HTML 生成详情视图，不复制第二个 HTML。

## 视觉和适配实现

- 壳层、间距、控件、表格、Tabs、Drawer、弹窗、Logo、颜色、排版和圆角全部从基础规范映射。
- 内容随视口变化，不使用固定宽屏画布伪造适配。
- 在窄端桌面宽度下，筛选可整组换行或进入“更多筛选”，关键操作必须可见。
- 表格可横向滚动；不添加移动端导航或卡片化替代表格。
- 动效只服务于 Drawer、确认、反馈和状态切换，避免装饰性大动画。

## 交付前验证

1. 在基础规范列出的全部支持视口实际打开 HTML。
2. 检查页面加载和核心交互无控制台错误或未处理异常。
3. 走通本次需求的主路径、取消、校验失败、提交失败和返回恢复。
4. 对照基础规范检查 Token、标准 Logo 和桌面适配；对照页面规范检查字段和层级。
5. 确认查询、重置、分页、Tabs、Drawer、确认和异步反馈按交互模式工作。
6. 确认所有可见按钮和链接都有响应，焦点可见，状态不只依赖颜色。
7. 断网重新打开 HTML，确认核心演示仍可完成。

未完成相应验证，不得声称高保真交互 HTML 已完成。
