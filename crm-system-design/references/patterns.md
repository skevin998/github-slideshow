# “我的客户”组件与交互模式

本文件只定义交互行为和组件使用方式。所有颜色、尺寸、间距、圆角、Logo 和分辨率使用 [基础设计规范](foundations.md)；页面层级、字段和业务流程使用 [页面规范](my-customers-pages.md)。

## 导航与上下文

- 保持现有全局菜单顺序，只保证“集团客户”展开且“我的客户”正确选中。
- 折叠侧栏后为菜单项提供 Tooltip；顶栏只放全局工具和账户信息，不放页面专属操作。
- 面包屑表达位置，当前项不可点击。需要精确返回来源状态时增加独立返回操作，但不能用它替代面包屑。
- 客户详情从列表打开新的浏览器标签。以客户编号复用已有详情标签，重复打开时聚焦已有标签。
- 公司详情和批量设置在当前客户详情标签内下钻。返回后恢复来源 Tab 的筛选、排序、页码、展示方式和滚动位置。
- 总公司分公司列表、关联分公司列表和关联门店页继续在当前标签下钻；返回遵循实际来源栈，不允许固定跳回错误页面。
- 下钻页返回按钮位于面包屑下方、白色内容上方的独立浅灰区域，靠左并垂直居中。

## 内容和模块

- 列表用于扫描、比较、筛选、选择和常用操作，不承载实体全部信息。
- 详情按“面包屑 → 实体摘要 → 业务 Tabs → 当前 Tab 内容”组织。
- 每个白色模块只承担一个职责；避免多层带边框卡片嵌套，优先用留白、标题、Tabs 和分隔线建立层级。
- 页面级主操作只出现一次；局部操作必须放在它所控制的内容附近。
- 长名称、空值、加载、错误和筛选无结果不得导致模块高度或工具栏位置无序跳动。

## Tabs

- 平级业务域使用 Ant Design v4 线型 `Tabs`；流程阶段使用 `Steps`，不得互换。
- Tabs 的所有视觉参数和业务模块内边距使用基础规范中的 Token；不得等分拉伸、插入空占位或用通用 `Space` 模拟 Tab 布局。
- Ant Design v4 实现使用 `tabBarGutter` 绑定基础规范中的相邻间距 Token。
- 每个 Tab 维护独立状态，至少包含草稿筛选、已提交筛选、排序、页码、每页条数、展示方式和滚动位置。
- 切回 Tab 时恢复离开前状态。当前 Tab 不写入 URL，不支持深链接；页面刷新后恢复初始状态，不跨刷新持久化。
- Tab 名称应简短稳定；只有数量能帮助用户决策且更新规则明确时才显示徽标。

## 同一列表的多视角切换

- 同一业务对象的不同表达方式使用按钮式单选分段控件；它是内容视角，不得伪装成新的 Tabs 或页面层级。
- Ant Design v4 使用按钮样式 `Radio.Group` 或等价行为，不使用 v5 `Segmented`。
- 每个视角分别保留已提交筛选、页码和内容区滚动位置；切换视角不清空其他视角状态。公司视角切换保持当前页面滚动位置，不主动滚动至顶部，避免操作栏上下移动。
- 只在当前视角需要时呈现搜索区。图谱等不可搜索视角必须完整移除搜索控件，而不是禁用或隐藏后保留空占位。
- 表格视角的行点击和行内操作必须指向同一目标；行内按钮需阻止事件冒泡，避免重复导航。
- 关系图节点必须可键盘聚焦并带有类型文字；连线只表达关系，不能承担唯一含义。

## 表单与筛选

- 筛选区紧邻其控制的数据。输入、选择、清空字段或按回车不自动查询，只有点击“查询”才更新结果。
- 草稿值和已提交筛选值必须分离。“重置”清空全部条件、恢复未筛选结果并回到第 1 页。
- “查询”和“重置”成组；新增、导入、批量操作组成另一操作组。空间不足时整组换行，不允许无序拆散。
- Select 的箭头位置、控件高度和筛选间距均使用基础规范 Token；选中值和占位文字不得与箭头重叠。
- 次要条件可收入“更多筛选”，但必须显示生效条件数量，并让已应用值可发现。
- 新增和编辑使用顶部标签的纵向表单。必填、格式和业务校验来自实际规则，不从截图外观猜测。
- 失焦和提交时显示字段附近错误；服务端失败保留输入；提交期间防止重复提交。

## 按钮与操作

- `primary`：当前操作组的查询、创建或提交。
- `default`：重置、取消、返回和次要批量操作。
- `link`/`text`：详情、编辑等行内操作。
- `danger`：删除等破坏性操作。删除必须二次确认并说明对象和后果。
- 常规与表格工具栏按钮使用基础规范中各自的高度 Token；同组间距也由基础规范控制。
- 单行可见操作尽量不超过 3 个，低频操作收入 `Dropdown`。图标不能替代不常见操作名称。
- 其他操作是否确认、审批、填写原因或记录审计，按具体需求决定。

## 表格

- 表头使用浅底色，数据行主要使用横向分隔线，不添加无必要竖线；行高使用基础规范 Token，表头不吸顶。
- 第一核心身份列优先突出；文字左对齐，可比较数字右对齐，操作列右对齐。
- 含“操作”列的表格将该列固定在右侧，横向滚动时始终可见；表头与数据单元格同步固定，使用不透明背景和左侧弱阴影区分滚动内容。仅横向固定，表头仍不吸顶。没有操作列的表格不固定末列。
- 日期默认使用 `YYYY-MM-DD HH:mm`。只有真正无值时显示 `-`，不得用它表示加载或异常。
- 长且非敏感内容使用 `ellipsis` 配合 Tooltip/Popover；核心实体名称在截断影响识别时可换两行。
- 排序、筛选和行选择必须显示当前状态；横向滚动优于过度压缩列宽。
- 只有存在有效批量操作时才显示选择列。

## 标签、反馈和加载

- 状态色使用基础规范中的语义 Token，并同时显示文字；不得只用彩色圆点表达业务状态。
- 混合结果同时显示成功和失败数量，并提供详情入口。
- 首次结构加载使用 `Skeleton`；局部刷新使用表格或组件 loading，保留不受影响的上下文。
- 提交按钮立即进入 loading；轻量成功使用 `message`，重要或异步结果使用 `notification`。
- 筛选无结果显示“未找到符合条件的数据”并提供清除筛选；首次无数据应解释下一步。
- 局部异常在对应区域使用 `Alert` 并提供重试；整页异常使用 `Result`。
- 失败后保留可恢复输入或上传文件，不伪装为成功。

## 分页与批量选择

- 全部列表使用同一分页器，位于数据区域底部，整组右对齐。排列顺序固定为“共 N 条 → 上一页 → 页码 → 下一页 → 每页条数”。不再使用左侧总数、记录范围与右侧控件分离的布局。
- 单页及空结果仍显示分页器；首页禁用上一页，末页禁用下一页。翻页实际更新记录，各列表保留独立页码和每页条数。
- 默认 10 条/页，可选 10、20、50、100；筛选或改变每页条数后回到第 1 页。
- 批量选择只作用于当前页；表头全选只选择当前页可选数据，翻页后清空，不提供跨页全选。
- 批量操作显示已选数量，并在执行前说明有效、无效和受影响对象。
- 异步批量任务记录任务编号、操作人、开始/结束时间及成功、失败、待处理数量；支持时提供失败明细。
- 重试失败项前必须确认幂等和重复创建规则。

## Drawer、详情与返回

- 新增、编辑和快速查看优先使用右侧 `Drawer`；宽度使用基础规范 Token。不得改为独立页或新增/编辑 Modal。
- Drawer 保留背景上下文；内容区滚动，标题和底部操作区固定。
- Drawer 标题栏的关闭图标使用固定尺寸按钮容器，并在容器内水平、垂直居中；图标图形不得依赖文本字符基线定位。
- 关闭无修改 Drawer 可直接退出；存在未保存修改时按待确认规则处理。
- 成功后只刷新关联数据，不重置背景页的筛选、页码、Tab、展示方式和滚动。
- 只读详情使用 `Descriptions`、信息网格或语义模块，不用禁用表单伪装。

## 业务流程、禁用与权限

- 页面设计必须同时说明触发条件、前置校验、状态流转、成功结果、失败恢复和必要审计。
- 非法状态流转不显示对应操作。业务状态暂不可用时可禁用，并解释原因。
- 当前版本不主动设计角色、操作或数据权限；不得把业务状态禁用误写成权限不足。
- 异步流程应覆盖提交、排队、执行中、成功、部分失败、失败和可重试状态。
- 删除必须说明是否可恢复。其他确认、审批和脱敏规则以 [待确认问题](open-questions.md) 为准。

## 命名

- 页面名使用业务对象和任务；按钮使用“动词 + 对象”；Tabs 使用稳定的名词短语。
- 同一业务状态只使用一套词汇，避免“已完成”“执行完成”“完成”等无意混用。
- 代码组件使用语义名称，如 `CustomerSummary`、`CompanyFilterBar`、`BatchJobStatusTag`，不得按颜色或位置命名。
